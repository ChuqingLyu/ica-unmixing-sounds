About this project

This is a small project about ICA (Independent Component Analysis) for K-12 learners. Kids record everyday sounds from home and the neighborhood, the computer mixes them as if several microphones in one room heard them at once, and then ICA pulls them apart again using only the mixed recordings.

Everything runs in your browser. You can drag, listen and compare. No formulas needed.

This page needs JavaScript to load the sounds.

Where the idea came from

I wanted kids to meet ICA somewhere familiar and fun. The point isn't the math. It's to make the cocktail party problem something they can actually hear and see being solved.

The cocktail party problem: in a noisy room you can still follow one friend's voice. Can a computer pull one sound out of a mix too?

The activity

I ran this as a summer-vacation project assignment. Over two weeks, about 6 Grade 7–8 students from Bocuide School, Guangzhou recorded sounds from their neighborhoods, homes, and communities with boom-pole microphones.

Then we mixed their sounds and unmixed them with ICA, using the tools on this page.

Why this activity matters

  • Their own data. Kids turn everyday sounds into data they collected themselves, so the data belongs to them and they learn what data really is.
  • A real AI problem, close to home. They meet the cocktail party problem (source separation), a real AI problem, in their own surroundings.
  • From listening to learning. It connects listening, a skill they already have, to how a machine can learn without labels.

Why an activity instead of formulas

  • ICA is usually taught with matrices and probability. Kids without that background have nothing to build on; some of my students had no prior knowledge to grasp ICA at all.
  • Here they collect the sounds, hear the mix, and turn the dial themselves, so the idea comes from experience first.
  • The math steps (centering, whitening, rotating) match steps they already did by hand.
  • The formulas can come later.

What is ICA?

Unsupervised learning

In unsupervised learning, the computer gets no answers or labels. It finds the patterns in the data by itself. K-means clustering is another example; I made a small project about it too: K-means palette.

ICA

ICA finds the separate sounds hidden in mixed recordings. It does this by looking for parts that are as independent from each other as possible.

Behind the scenes: training the model

These are real outputs from one run of FastICA (the version of ICA on this page) on the three demo sounds, with the default mix from step 2 and the same starting point as the first press of “Separate”. The figures come from tools/make_figures.py, a numpy copy of the code in ica.js. I checked that both take the same 7 rounds and print the same numbers. The matches come out near 1.00 because the computer mixes the sounds perfectly in sync, with no echo.

Step 1 · Get the sounds ready

I cut a 9-second piece from each recording, made it mono at 16,000 samples per second, and evened out the loudness with ffmpeg (tools/make_audio.sh). That's 144,000 numbers per sound. The three sounds are almost unrelated to begin with: the correlation between any two of them is below 0.01.

Step 2 · Mix, center, whiten

The script mixes the sounds with the default loudness table, moves each mic recording to the middle (centering), then stretches it to be round (whitening). After this, the only thing left to learn is how to turn.

Step 6 · The code for one round

This is the loop from fastICA() in ica.js that runs once per round:

var Wn = [];
for (i = 0; i < m; i++) {
  for (t = 0; t < n; t++) {                       // wz = this output, right now
    for (var v = 0, j = 0; j < m; j++) v += W[i][j] * Z[j][t];
    wz[t] = v;
  }
  var row = new Array(m).fill(0), gp = 0;
  for (t = 0; t < n; t++) {                       // push w toward a less bell-shaped output
    var g = Math.tanh(wz[t]);
    gp += 1 - g * g;
    for (j = 0; j < m; j++) row[j] += Z[j][t] * g;
  }
  for (j = 0; j < m; j++) row[j] = row[j] / n - (gp / n) * W[i][j];
  Wn.push(row);
}
Wn = symDecorrelate(Wn);                          // keep outputs at right angles
var change = 0;                                   // how much did the dial move this round?
for (i = 0; i < m; i++) {
  for (var dot = 0, j = 0; j < m; j++) dot += Wn[i][j] * W[i][j];
  change = Math.max(change, Math.abs(Math.abs(dot) - 1));
}
W = Wn;
if (opts.onRound) opts.onRound(it, W, change);
if (change < tol) { converged = true; break; }

In plain words: for each output, look at what it sounds like right now, nudge it toward a spikier, less bell-shaped sound, keep the outputs at right angles to each other, and stop when the nudge gets tiny.

Is this AI?

  • It learns from data, without labels. Nobody tells it which sound is which. The rounds you saw above are its training.
  • Real products face the same problem. Voice assistants and hearing aids also need to pull one sound out of a mix (this is called source separation). Today they often use deep learning for it.
  • You can look inside it. What ICA learns is a small table of numbers (a 3×3 unmixing table here) that you can print and check, like in step 5 above. That makes it a nice first example of explainable AI, which is what my research is about.

Where ICA shows up in real life

  • Pulling a voice out of background noise, for example in hearing aids or voice assistants.
  • Separating the singing from the music, like making a karaoke track.
  • Cleaning brain-wave recordings (EEG) by removing the signals made by eye blinks.
  • Separating overlapping signals picked up by sensors, or mixed together in images.
